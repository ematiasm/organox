# Config, routes, and concurrent draft races (#116)

Objective: Fix silent config clamping, hardcoded `POOL_MAX_CONNECTIONS` and `FRONTEND_DIR`, per-request `ServeDir` reconstruction, exact `/api` SPA fallback, duplicate concurrent draft creation, and out-of-transaction `set_customer`/`set_supplier` active checks from GitHub issue #116.
Branch: `fix/config-routes-draft-races` | Delivery: `single-pr` (maintainer-approved single PR, ~814 authored lines across 7 commits; ~387 lines are new tests) | Runner: `cargo test` (`make migrate`, `make prepare`, `make check`)

## Specs

S1. Fail-fast config validation & configurable pool/frontend settings (`src/config.rs`, `src/db.rs`, `src/main.rs`, `.env.example`, `.env.prod.example`, `compose.prod.yaml`, `tests/config.rs`, `tests/deploy.rs`).
  - Issue quote: "1. **Silent config clamping (`src/config.rs:40, 47`):** Unlike `APP_LOGIN_MAX_FAILURES < 1` (which fails fast at startup), `APP_LOGIN_BLOCK_MINUTES <= 0` and `APP_LOGIN_IP_MAX_PER_MINUTE == 0` are silently clamped via `.max(1)`, contradicting the module's fail-fast contract (`src/config.rs:3-4`). `POOL_MAX_CONNECTIONS` is also hardcoded in `src/db.rs:9`."
  - Issue quote: "Fail fast in `Config::from_env()` when `login_block_minutes < 1` or `login_ip_max_per_minute < 1`, and make `frontend_dir` (and optionally `db_max_connections`) configurable."
  - Reject `APP_LOGIN_BLOCK_MINUTES < 1` (and overflow on `* 60`), `APP_LOGIN_IP_MAX_PER_MINUTE < 1`, and `APP_DB_MAX_CONNECTIONS < 1` in `Config::from_env()`, remove silent `.max(1)` clamping from `account_policy()` / `ip_policy()`, wire `APP_DB_MAX_CONNECTIONS` (default `5`) into `db::connect`, wire `APP_FRONTEND_DIR` (default `"frontend/build"`), and expose both in `.env.example`, `.env.prod.example`, and `compose.prod.yaml` so `tests/deploy.rs` stays green.

S2. SPA serving & `/api` fallback (`src/routes.rs`, `src/lib.rs`, `src/main.rs`, `tests/health.rs`).
  - Issue quote: "2. **SPA serving (`src/routes.rs:14-65`):** `FRONTEND_DIR` is a hardcoded `const` (despite its doc comment saying it is configurable), `spa_fallback` constructs a fresh `ServeDir`/`ServeFile` on every fallback request, and line 54 checks `starts_with(\"/api/\")` so exact `/api` falls through to `index.html` instead of returning JSON `404`."
  - Issue quote: "Instantiate `ServeDir` once at router construction and return RFC 7807 `404` for exact `/api` as well as `/api/*`."
  - Carry `frontend_dir: PathBuf` on `AppState` (with `.with_frontend_dir(...)` builder, defaulting to `"frontend/build"`), instantiate `ServeDir::new(&frontend_dir).fallback(ServeFile::new(frontend_dir.join("index.html")))` once in `router_with_limits`, and return RFC 7807 `404` (`application/problem+json`) when `path == "/api" || path.starts_with("/api/")` (leaving sibling paths like `/api-docs` to the SPA).

S3. Concurrent draft creation & transactional party active checks (`migrations/0036_single_draft_per_operator.sql`, `src/sales/{service,repository}.rs`, `src/purchases/{service,repository}.rs`, `tests/sales.rs`, `tests/purchases.rs`).
  - Issue quote: "3. **Concurrent draft creation (`src/sales/service.rs:137-153`, `src/purchases/repository.rs:81-111`):** Neither `sales` nor `purchases` has a partial unique index `(created_by) WHERE status = 'draft'`, so concurrent `POST .../draft` calls by the same user create duplicate drafts; `set_customer` and `set_supplier` also check `is_active` outside the update transaction."
  - Issue quote: "Enforce single open draft per operator with a partial unique index and check party `is_active` inside the draft update transaction."
  - Add partial unique indexes `sales_one_open_draft_per_user_idx` on `sales (created_by) WHERE status = 'draft'` and `purchases_one_open_draft_per_user_idx` on `purchases (created_by) WHERE status = 'draft'`.
  - Make `sales::open_draft` and `purchases::open_draft` race-free using `INSERT ... ON CONFLICT (created_by) WHERE status = 'draft' DO NOTHING RETURNING id` with bounded fallback `SELECT` returning `(existing_id, true)` for concurrent losers.
  - Lock the draft (`FOR NO KEY UPDATE`) and the party (`FOR SHARE` on `customers` / `suppliers`, matching `complete()` lock order) inside a single transaction in `sales::repository::set_customer` and `purchases::repository::set_supplier` to eliminate TOCTOU races with concurrent deactivation.
